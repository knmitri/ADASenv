# Analytical Reeds–Shepp Connector

## Status and scope

`ReedsSheppConnector::analytical_candidates` enumerates candidates from the
five canonical Reeds–Shepp family groups (CSC, CCC, CCCC, CCSC and CCSCC),
their 18 left/right/straight word types, and the time-flip, reflection,
combined and backward constructions. It returns every feasible candidate
generated by those closed-form constructions, in increasing geometric length.
Its formula cases and symmetry transforms map to OMPL's canonical 18 path
types, and its shortest distances passed the 1,351-case OMPL comparison below.
This is implementation-level mathematical validation, not a formal proof or
production/safety qualification.

The default connector remains the pre-existing numerical implementation.
Select the analytical implementation as the default with
`-DADAS_REEDS_SHEPP_DEFAULT_ANALYTICAL=ON`; either implementation can also be
selected explicitly through `ReedsSheppImplementation`.

The equations and path-family enumeration follow J. A. Reeds and L. A. Shepp,
“Optimal paths for a car that goes both forwards and backwards,” *Pacific
Journal of Mathematics*, 145(2), 1990, pp. 367–393, DOI
[10.2140/pjm.1990.145.367](https://doi.org/10.2140/pjm.1990.145.367).
OMPL’s public `ReedsSheppStateSpace` implementation is the implementation
reference for formulas 8.1–8.11 and symmetry coverage:
[source](https://github.com/ompl/ompl/blob/main/src/ompl/base/spaces/src/ReedsSheppStateSpace.cpp).
The paper contains typographical errors in formulas 8.3/8.4 and 8.11; the
corrected forms used here are those documented by the OMPL reference.

This is a geometric path solver, not a complete parking planner. Reeds–Shepp
paths do not route around obstacles. The connector checks generated paths
against the existing collision checker; global obstacle avoidance remains the
responsibility of Hybrid A* or another obstacle-aware planner. Speed profiling,
actuator-feasible steering transitions, and closed-loop safety qualification
remain separate concerns.

## Normalization and segment convention

Let the vehicle start pose be \(q_s=(x_s,y_s,\theta_s)\), goal pose be
\(q_g=(x_g,y_g,\theta_g)\), and minimum turning radius be
\(\rho = L/\tan(\delta_{\max})\), where \(L\) is wheelbase and
\(\delta_{\max}\) is the steering-angle limit. In the start vehicle frame,
normalized by \(\rho\):

\[
x = \frac{\cos\theta_s(x_g-x_s)+\sin\theta_s(y_g-y_s)}{\rho},\quad
y = \frac{-\sin\theta_s(x_g-x_s)+\cos\theta_s(y_g-y_s)}{\rho},\quad
\phi = \operatorname{mod}_{2\pi}(\theta_g-\theta_s).
\]

`mod2pi` maps to \([-\pi,\pi]\). A curve segment has unit normalized
curvature \(+1\) for left or \(-1\) for right; a straight has zero curvature.
Its signed normalized length \(s_i\) is positive forward and negative reverse.
For a curve, heading change is \(c_i s_i\), where \(c_i\in\{+1,-1\}\).
Physical signed segment lengths are \(s_i\rho\); path length is
\(\rho\sum_i |s_i|\).

For example, the exact normalized integration of one constant-curvature
segment is:

\[
\theta' = \theta + c s,\quad
x' = x + \frac{\sin\theta'-\sin\theta}{c},\quad
y' = y + \frac{\cos\theta-\cos\theta'}{c}.
\]

For a straight, \(x'=x+s\cos\theta\), \(y'=y+s\sin\theta\), and
\(\theta'=\theta\). The solver re-integrates every candidate and rejects it if
the endpoint does not match the normalized target within numerical tolerance.

## Closed-form family equations

Use `polar(a,b) = (r,\theta)`, where \(r=\sqrt{a^2+b^2}\) and
\(\theta=\operatorname{atan2}(b,a)\). Angles in the following formulas are
wrapped with `mod2pi`; feasibility inequalities allow only small
floating-point tolerance at zero or inverse-trigonometric boundaries.

### CSC

Formula 8.1, \(L^+S^+L^+\):

\[
(u,t)=\operatorname{polar}(x-\sin\phi,\;y-1+\cos\phi),\quad
v=\operatorname{mod}_{2\pi}(\phi-t),
\]
with \(t,v\ge0\). Formula 8.2, \(L^+S^+R^+\):

\[
(u_1,t_1)=\operatorname{polar}(x+\sin\phi,\;y-1-\cos\phi),\quad
u=\sqrt{u_1^2-4},\quad
t=\operatorname{mod}_{2\pi}(t_1+\operatorname{atan2}(2,u)),\quad
v=\operatorname{mod}_{2\pi}(t-\phi),
\]
with \(u_1\ge2,\ t,v\ge0\). Reflection generates RSR and RSL respectively.

### CCC

Formula 8.3/8.4, \(L^+R^-L^+\):

\[
(\rho_1,\theta)=\operatorname{polar}(x-\sin\phi,\;y-1+\cos\phi),\quad
u=-2\arcsin(\rho_1/4),\quad
t=\operatorname{mod}_{2\pi}(\theta+u/2+\pi),\quad
v=\operatorname{mod}_{2\pi}(\phi-t+u),
\]
with \(\rho_1\le4,\ t\ge0,\ u\le0\). Reflection gives RLR. The backward
construction applies the same formula to the goal-frame reversed coordinates,
then reverses the outer segment order.

### CCCC

Formula 8.7:

\[
\xi=x+\sin\phi,\quad\eta=y-1-\cos\phi,\quad
\varrho=(2+\sqrt{\xi^2+\eta^2})/4,\quad
u=\arccos\varrho.
\]

The auxiliary `tauOmega(u,-u,xi,eta,phi)` gives \(t,v\), producing
\(L^+R^+L^-R^-\) with lengths \((t,u,-u,v)\); require
\(\varrho\le1,\ t\ge0,\ v\le0\). Formula 8.8 uses
\(\varrho=(20-\xi^2-\eta^2)/16,\ u=-\arccos\varrho\), then
`tauOmega(u,u,...)`, lengths \((t,u,u,v)\), and requires
\(0\le\varrho\le1,\ u\ge-\pi/2,\ t,v\ge0\). Reflection produces the
opposite turn words.

For both equations, with \(\Delta=\operatorname{mod}_{2\pi}(u-v)\), define

\[
A=\sin u-\sin\Delta,\quad B=\cos u-\cos\Delta-1,\quad
\tau=\operatorname{mod}_{2\pi}\!\left(
\operatorname{atan2}(\eta A-\xi B,\xi A+\eta B)
+\begin{cases}\pi,&2(\cos\Delta-\cos v-\cos u)+3<0\\0,&\text{otherwise}\end{cases}
\right),\quad
\omega=\operatorname{mod}_{2\pi}(\tau-u+v-\phi).
\]

### CCSC

Formula 8.9, \(L^+R^-S^-L^-\):

\[
(\varrho,\theta)=\operatorname{polar}(x-\sin\phi,\;y-1+\cos\phi),\quad
r=\sqrt{\varrho^2-4},\quad u=2-r,\quad
t=\operatorname{mod}_{2\pi}(\theta+\operatorname{atan2}(r,-2)),\quad
v=\operatorname{mod}_{2\pi}(\phi-\pi/2-t).
\]

Require \(\varrho\ge2,\ t\ge0,\ u,v\le0\); the word lengths are
\((t,-\pi/2,u,v)\). Formula 8.10, \(L^+R^-S^-R^-\), uses
\[
(\varrho,t)=\operatorname{polar}(-\eta,\xi),\quad
\xi=x+\sin\phi,\quad\eta=y-1-\cos\phi,\quad
u=2-\varrho,\quad v=\operatorname{mod}_{2\pi}(t+\pi/2-\phi),
\]
with the same feasibility signs and lengths \((t,-\pi/2,u,v)\). Reflection
and backward constructions produce the other CCSC words.

### CCSCC

Corrected formula 8.11, \(L^+R^-S^-L^-R^+\):

\[
\xi=x+\sin\phi,\quad\eta=y-1-\cos\phi,\quad
(\varrho,\theta)=\operatorname{polar}(\xi,\eta),\quad
u=4-\sqrt{\varrho^2-4},
\]
\[
t=\operatorname{mod}_{2\pi}\operatorname{atan2}
((4-u)\xi-2\eta,\;-2\xi+(u-4)\eta),\quad
v=\operatorname{mod}_{2\pi}(t-\phi).
\]

Require \(\varrho\ge2,\ u\le0,\ t,v\ge0\); the word lengths are
\((t,-\pi/2,u,-\pi/2,v)\). Reflection gives the second CCSCC word.

## Symmetries, candidate generation, and collision selection

Every base equation is evaluated for the four standard images:

- identity: \((x,y,\phi)\);
- time flip: \((-x,y,-\phi)\), followed by negating every signed length;
- reflection: \((x,-y,-\phi)\), followed by swapping left and right;
- both: \((-x,-y,\phi)\), with both operations.

CCC and CCSC also evaluate the backward constructions using
\((x_b,y_b)=(x\cos\phi+y\sin\phi,\;x\sin\phi-y\cos\phi)\), with segment
order/word adjustments. Together these generate the canonical symmetry
constructions for the 18 Reeds–Shepp word types used by the OMPL reference
(some family equations have more than one construction).

`analytical_candidates` is deliberately independent of obstacles and returns
the geometric candidates. `connect` sorts those candidates by geometric
length, enforces the requested initial direction, samples each candidate,
and returns the first path accepted by the existing collision checker and
goal evaluator. The numerical implementation is retained and selectable.
The connector clears its output vector before dispatching either implementation,
including on failure; this makes failure output deterministic and is a change
from the previous numerical connector's stale-output behavior.

The deadline is checked before candidate sampling and periodically during
sampling. Analytical candidate enumeration is currently a bounded synchronous
operation without an internal deadline check; a deadline that expires during
enumeration is observed only when enumeration returns.

## Validation

The normal C++ suite exercises all 18 word shapes, endpoint closure on a
deterministic pose grid, reflection/time-flip/reversal distance invariance,
forward/reverse straight reference distances, and collision-filtered
connection. `reeds_shepp_verification_test` additionally checks signed
length/gear conversion, physical length sums, curvature bounds, independent
endpoint integration, zero-length paths, symmetry segment ordering, sorted
candidates, exact cusp stop markers, a blocked-shortest/clear-longer connector
case, deadlines, failure output, and configured numerical/analytical dispatch.

The optional OMPL test compares shortest distances over the 343-pose grid,
eight named edge/maneuver fixtures, and 1,000 reproducible random poses
(seed `0x5EED1234`). It prints max, mean, p50, p95 and p99 absolute error,
along with the OMPL version, compiler and build configuration.

On Windows, install OMPL with vcpkg and configure the optional target:

```powershell
git clone https://github.com/microsoft/vcpkg C:\vcpkg
& C:\vcpkg\bootstrap-vcpkg.bat -disableMetrics
& C:\vcpkg\vcpkg.exe install ompl:x64-windows-static --disable-metrics
cmake -S . -B build\ompl `
  -DCMAKE_TOOLCHAIN_FILE=C:\vcpkg\scripts\buildsystems\vcpkg.cmake `
  -DVCPKG_TARGET_TRIPLET=x64-windows-static `
  -DCMAKE_MSVC_RUNTIME_LIBRARY=MultiThreaded `
  -DADAS_ENABLE_OMPL_REFERENCE_TESTS=ON
cmake --build build\ompl --config Release --target reeds_shepp_ompl_reference_test
ctest --test-dir build\ompl -C Release -R reeds_shepp_ompl_reference_test --output-on-failure
```

The vcpkg CMake config exports `ompl::ompl`, which the optional target links
directly. The analytical implementation remains opt-in by default; this
verification did not change the default planner configuration or remove the
numerical fallback.

Verification run on 2026-11-08 with OMPL 2.0.2, MSVC 19.40.33813, and Release
passed all 1,351 comparisons. Absolute shortest-distance errors were:
maximum \(2.84217094304\times10^{-14}\) m, mean
\(4.42396345727\times10^{-15}\) m, p50 \(0\) m, p95
\(1.42108547152\times10^{-14}\) m, and p99
\(2.84217094304\times10^{-14}\) m. The cases include the original 343-pose
grid, named forward-only/reverse-only/mixed/multiple-cusp and degenerate cases,
and 1,000 poses generated with seed `0x5EED1234`.

The first executable comparison exposed a near-coincident-pose candidate that
was accepted by the previous normalized endpoint tolerance (`2e-8`) despite
not closing accurately relative to the pose displacement. The solver's
endpoint tolerance was tightened to `1e-10`; the near-coincident OMPL case and
the 1,351-case comparison then passed. After this correction, Debug and Release
tests passed with the analytical default both enabled and disabled (3/3 CTest
tests per configuration), and Python regressions passed (16/16). This is a
numerical acceptance correction, not a change to the path-family equations or
default implementation.

The deadline regression aborted a million-metre candidate after 51 ms with a
50 ms sampling budget and an empty result. An already-expired deadline returned
after 37 microseconds in this run; that time includes the uncancellable
candidate enumeration. These timings are environment-specific and are not a
real-time performance guarantee.
